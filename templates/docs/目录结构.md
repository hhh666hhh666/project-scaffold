# 目录结构

> 这是本项目的**现状图示**：只画层级与各文件职责，一句话一条。
> 谁有内容、谁对谁是真相源，以[文档地图](./README.md#文档地图)为准——那张表才是权威索引，这里只是把同一批文件画成树。
> 与文件系统不一致时以文件系统为准，并顺手把本文件改回。

分成两棵树看：**先看仓库根（文档散在哪），再看 `docs/` 子树（文档体系内部长什么样）**。两者是同一批文件的两个视角，不重复列。

## 一、仓库根：文档都在哪

以仓库根为根，只画**与文档相关**的东西——代码目录（`backend` / `frontend`）只标出位置，内部结构见各自的 README（尚未建就先不写）。

```
<仓库根>/
├── README.md                       # 上手：定位 / 功能 / 跑起来 / 配置 / CI 与部署
├── GLOSSARY.md                     # 领域术语表（只收本项目独有的词）
├── PRODUCT.md                      # 产品真相：受众 / 用途 / 定位 / 语气 / 约束（由 impeccable 填充）
├── DESIGN.md                       # 视觉系统可读快照（由 impeccable 从 tokens.css 派生）
├── CHANGELOG.md                    # 版本变更记录（真相源是 git tag）
├── AGENTS.md                       # 给 AI 的规矩（跨工具摘要，只做路由）
├── CLAUDE.md                       # Claude Code 入口：只导入 AGENTS.md 与四条规则
├── .env.example                    # 环境变量样例（.env 不入库）
├── .gitattributes                  # 强制 *.sh / *.conf 以 LF 入库
├── .scaffold.json                  # 生成记录：脚手架来源与本次参数（不是当前配置真相源）
├── .github/dependabot.yml          # 依赖升级提案（Maven / npm / GitHub Actions，只开 PR）
├── docker-compose.dev.yml          # 本机开发只起数据库
├── docker-compose.prod.yml         # 云上编排（可选章节）
├── .codebuddy/                     # AI 侧的工作规则与命令
│   ├── rules/                      # 常驻规则（权威版本；WorkBuddy 自动加载，Claude Code 经 CLAUDE.md 导入）
│   │   ├── unresolved-items.md     # 未决事项必须落 docs/todo/
│   │   ├── docs-with-code.md       # 改代码 = 改文档
│   │   ├── session-log.md          # 会话工作台怎么建
│   │   └── design-skills.md        # 外部设计 skill 的使用纪律
│   └── commands/                   # 斜杠命令
│       └── wrap-up.md              # 收尾自检
├── docs/                           # 文档体系主体 —— 见下一棵树
├── scripts/                        # 机械守卫脚本（提交前 / CI 上跑）
│   ├── ${LINK_CHECK_SCRIPT}        # 链接与路径引用自检
│   ├── ${TODO_ARCHIVE_SCRIPT}      # 断言已结案待办都已归档
│   ├── ${MODULE_TEST_SCRIPT}       # 断言带 Controller 的模块都配了测试类
│   └── ${VERSION_SCRIPT}           # 版本号与 git tag 对齐自检
├── deploy/                         # 要放到服务器上的部署侧配置模板（可选章节）
├── backend/                        # 后端（Spring Boot）
└── frontend/                       # 前端（Vue 3）
```

## 二、`docs/` 子树：文档体系内部

```
docs/                               # 文档根：与代码同仓、同 PR 评审（Docs as Code）
├── README.md                       # 文档地图：路径 / 用途 / 读者 / 真相源 四列表，只回答「东西在哪」
├── 目录结构.md                     # 本文件：两棵带注释目录树，只画形状
├── adr/                            # 决策结论卡片，一条一卡、只追加不改
│   └── README.md                   # 收录标准（难反转 / 不看上下文会意外 / 有真实取舍）与格式
├── design/                         # 设计文档，按主题拆分
│   ├── API.md                      # 怎么看真实接口 + 通用约定（刻意不维护 endpoint 表）
│   ├── 前端.md                     # 页面流、路由、状态与 API 边界
│   ├── 数据模型.md                 # 实体关系、生命周期、历史一致性
│   └── 设计skill清单.md            # 外部设计 skill 的角色与禁区（档案）
├── development/                    # 开发协作
│   └── contributing.md             # 分支 / 提交 / PR 约定与文档纪律
├── operations/                     # 运行与运维（按需自建）
│   └── 内存策略.md                 # 可选章节：内存花在哪、怎么算预算、止损线
├── requirements/                   # 范围约束
│   └── scope.md                    # 定位、范围、明确不做、已定约束
├── testing/                        # 可选章节：测试规范（README.md + 系统说明.md）
├── todo/                           # 未决事项唯一入口（不许在别处开待办清单）
│   ├── README.md                   # 命名规则 + 索引表 + 「已归档」区 + 「已定，不用再想」表
│   ├── YYYY-MM-DD-TODO-*.md        # 按主题拆文件，日期是创建日
│   └── archive/                    # 已结案待办：结案即 git mv 进来，只留档、不再变更
└── worklog/                        # 会话工作台：一次会话一份，只对创建它的那次会话有意义
    ├── README.md                   # 常驻说明；兼作「目录不消失」的占位
    └── YYYY-MM-DD-HHmm-*.md        # 按会话生成，随时可删
```

## 怎么读

- 缩进表示目录层级；`#` 后面是这一条**只做一件事**的说明。
- **第一棵树画「文档散在哪」**（含根目录文件），**第二棵树画 `docs/` 体系内部**；两棵树互不重复——`docs/` 在第一棵里只作为**一个节点**出现。
- 带 `*` 的条目表示「同类文件若干」，不逐个列——`adr/` 只追加、`todo/` 按主题增删、`worklog/` 按会话生成且随时可删，列全了反而天天要改。
- **决策只有 `adr/` 记**：结论与**被否的选项**都在同一张卡里（后者写在 Considered Options 一节）；过程记录归 `worklog/`，但它是过程、不是事实源。
- 两棵树里画到的文档都进[文档地图](./README.md#文档地图)，**用途与真相源一律以那张表为准**，本文不复述。

## 维护

- 改动**两处**任一即需回来改树：① 根目录的文档增删（第一棵）；② `docs/` 结构增删（第二棵）。
- ⚠️ **改一处要同步另一处**：本文件与[文档地图](./README.md#文档地图)是同一批文件的两个视角——**树看形状，表看用途与真相源**，改结构时一起改。
- 树里的路径都写成**行内代码**（不是链接），因为不少路径在树里是示意（如 `NNNN-*.md`）；真要跳到文档，走文档地图的链接。
- 想补齐某个目录属于未决事项 → 记到 `docs/todo/`，不在这里排队。
