# 前端从「只测纯逻辑」扩展到「含组件测试范本」

Status: accepted（2026-10-18）

骨架原先只给前端逻辑单测（请求层、登录态、路由守卫），组件测试的触发条件写成「多个页面复用同一段自研逻辑或纯逻辑密度显著上升」，骨架阶段不成立。现在提前纳入**一个组件测试范本**：页面即将成为代码主体，没有范本时开发者不会自发写组件测试，等到「触发条件成立」那天也已经欠了一堆页面测试。

范本只演示**组件状态与数据流的衔接**（加载中 / 成功 / 失败三种显示），不引入浏览器、不引入视觉回归、不引入 e2e；请求用假函数替掉，组件测试仍然随手能跑。

## Considered Options

- **继续只测纯逻辑，等触发条件成立再补**：条件本身要靠人来判断，而且「新项目没有业务之前不需要」的判断在骨架阶段成立，在页面铺开之后就不再成立——届时没有可抄的形状，测试会长期缺席。
- **一步到位上 e2e（Playwright 等）**：强绑定具体业务场景与运行环境，骨架没有业务可测；维护成本远高于收益。
- **引入组件测试范本（选定）**：只多一个开发依赖（`@vue/test-utils`），跑法与现有 Vitest 完全一致，不需要新机器依赖。

## Consequences

- 前端测试体系从「纯逻辑」变为「逻辑 + 组件状态」，盲区缩小到「交互路径与视觉表现」；这两项仍靠人眼。
- 多一个开发依赖；版本登记进版本表，由一致性检查盯着。
- 组件测试**也归 `npm run test`**，没有新增门禁命令——门禁数量不变。
- lint、视觉回归、跨浏览器、e2e 的立场不变，仍在「明确不做」里。
- 本文取代 `templates/testing/系统说明.md` 里「骨架阶段不成立」的旧判断；那份文档已同步改写。
