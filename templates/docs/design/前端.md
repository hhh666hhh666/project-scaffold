# 前端

> **本文只讲 PC / Web 端**（`frontend/`，Vue 3 + Vite + TypeScript + Pinia，组件基座 **reka-ui + shadcn-vue（源码入库）+ Tailwind CSS v4**）。
> 若将来加移动端工程，另开一份文档，别往本文里塞。

**目的**：讲清前端页面的组织方式、状态与服务端数据怎么流转，以及哪些边界容易踩。

**读者**：要改前端的人。

**真相源**：**路由、页面清单、组件清单以代码为准**（`frontend/src/` 下的 `router/`、`views/`、`components/`、`stores/`、`api/`）。本文档只讲边界与约定，不复制那些清单。

> ✅ **设计系统的唯一真相源是 `frontend/src/styles/tokens.css`**——改颜色 / 间距 / 圆角只改它，组件不许写死值。
> 视觉系统的**人类可读快照是仓根 `DESIGN.md`**，**它从实现派生**，由 impeccable 生成，不手写。

## 路由与访问控制

路由定义见 `router/index.ts`。除登录注册外的路由需要登录态，由**路由守卫**统一拦截，token 存在 Store 里并做了持久化。

注意：路由守卫只挡「没登录」，**不挡「没有数据权限」**——后者由服务端判定（见 [API.md](./API.md)）。

## 页面与组件边界

- 页面组件按上面的路由划分，放在 `views/`
- **组件基座**：`components/ui/` 是 shadcn-vue 的**源码入库**（按需 `npx shadcn-vue@latest add` 拉取后即归属本仓库，可改）；业务件放 `components/`。
  引入新组件库前先查它的**内置文案语言**，避免满屏中文里飘几句洋文
- 可复用组件放在 `components/`
- 类型定义集中在 `types/`，应与后端 VO 对应；**它不是独立契约源**，后端结构变化时以接口文档输出为准
- ⚠️ **写弹窗宽度时 `sm:max-w-*` 必须一起覆盖**：shadcn 的 `DialogContent` 内置了 `sm:max-w-sm`，
  它带 `sm:` 修饰符、与 `max-w-3xl` **不同组**，`twMerge` 不会替你合并掉（只写后者实际只有 384px）
- **可点元素一律是真按钮**：行内动作用统一件（hover 下划线 + 键盘焦点环），别用 `div` 加 `@click`——键盘用户会丢焦点指示

## 状态与 API 访问

- Store 放全局状态：用户信息与 token（持久化）。定义在 `stores/`
- **列表页的「筛选状态」放网址（`route.query`），不放 Store**：刷新与前进后退都要能原样恢复条件。
  约定三条：**脏值忽略**（手改网址塞非法枚举要退回默认）、**默认值不写进网址**、**用 `replace` 而不是 `push`**
- ⚠️ **数组参数不能直接交给 axios**：它会把 `[1, 2]` 序列化成 `tagIds[]=1&tagIds[]=2`，而后端认的是重复参数名——
  筛选条件会**静默失效**。必须手工摊开
- HTTP 封装在 `api/request.ts`，统一处理 baseURL、token 注入、错误提示与响应解包
- 各领域的请求按模块拆分到 `api/` 下对应文件，不散落在组件里

## 界面主题（浅色 / 深色）

三档外观：**跟随系统 / 浅色 / 深色**。开关就是 `<html>` 上的 `dark` 类，颜色全部由 `tokens.css` 驱动——**不用逐个组件覆盖**。

- **自有样式不许写死色值**，一律走 token。可用变量名以 `tokens.css` 为准，**本文不复制清单**
- 主题偏好的 `localStorage` key 若同时写在 store 与 `index.html`（首屏防闪烁的内联脚本），改一处就必须一起改另一处，否则刷新会闪一下浅色

## 构建与类型检查

前端**只有类型检查与构建两个门禁**（`npm run typecheck` / `npm run build`）。

⚠️ `vite build` 走 esbuild 只剥离类型、不做检查，所以**类型错误只会被 `typecheck` 挡住，构建永远是绿的**。别以为构建过了就是好的。

### 材质语言（按本项目自己定的口味填）

| 层 | 管什么 | 用什么 |
|---|---|---|
| **铺底 = 面** | 页面底 / 卡片 / 表格 / 表单（绝大多数界面） | `canvas` / `surface` / `surface-2` / `tint-*`。**不用玻璃** |
| **浮层 = 玻璃或实底，逐件自定** | 弹窗 / 下拉 / 提示 / 抽屉 | 玻璃用 `.glass`；**用不用看实体预览逐件拍板** |
| 顶栏 / 侧栏 | 夹在两者之间 | 各自定一档，别和上面混用 |

⚠️ **三条硬规矩**：① 玻璃**背后必须有内容可透**，浮在纯白上等于白付性能；② **玻璃上不许放长正文**——正文永远在近白阅读面上；③ 系统开「减少透明度」时玻璃退化成实底。

具体数值与理由见 `frontend/src/styles/tokens.css` 的注释（**单一信息源，本文件不复述数值**）。
