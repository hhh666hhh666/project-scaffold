# TODO

按**主题**拆文件，不是按时间堆在一起——不同主题的紧迫程度差太远，混在一张清单里每次都得重读一遍。

## 命名

```
YYYY-MM-DD-TODO-<主题>.md
```

日期是**创建日期**，不是最后修改日期，所以后面怎么改都不用改名。主题写中文，一眼能看出是哪摊事。

## 文件格式

**新建的待办照下面的骨架写**：

```markdown
# 待办：<主题>

创建：YYYY-MM-DD · 状态：待办 · 优先级：高|中|低

## 背景
<为什么会有这条：现状是什么、卡在哪。两三句，别铺陈。>

## 可选方案
- **方案甲**：<做法> —— 代价：<…>
- **方案乙**：<做法> —— 代价：<…>

➡️ 倾向：<哪个，为什么>（还没定就写「暂未定，因为…」，**别只列选项不给倾向**）

## 待确认
<还缺哪块信息 / 等谁拍板 / 等什么前置。没有就写「无」。>

## 更新记录
- YYYY-MM-DD：<改了什么>
```

**四条硬约束**：

- **头三行（`# 待办：` / `创建：…` / 空行）固定**——本项目的归档守卫脚本只读头几行的 `状态：待办` 判断「结案了没」，别改这行的写法。
- `## 可选方案` 里**每给一个选项就要给倾向**；确实还没定，写清「为什么定不下来」，别让读者空手走。
- `## 更新记录` 是**追加**区，新的写在下、写明日期；**不改上面已有条目**。
- 文末可放一条 `> 关联：` 指到相关 ADR / 设计文档；**不写编号以外的东西**（编号是入口，内容在那边）。

## 结案即归档

一条待办解决完，把文件头那行 `状态` 改成 `已解决`，并**立刻 `git mv` 到 `archive/`**，同时把它从下面的主索引表移到「已归档」区。留档是为了能看出当初纠结过什么，但结案的不该再和未决的挤在同一张表里。

⚠️ 移动后文件深了一层，文内 `../` 相对链接要**多退一级**（`../adr/…` → `../../adr/…` 等），否则链接自检脚本会报红。三步怎么做见 [archive/README.md](./archive/README.md)。
