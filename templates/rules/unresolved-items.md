# 未决事项落盘

对话会关、上下文会被压缩，只有文件不会。**任何还没定的事，必须在本次回复结束前**变成 `docs/todo/` 下的文件——在回复里说一句「以后可以优化」不算完成。

## 触发信号（命中任一即视为未决）

- **措辞**：以后 / 回头 / 下次 / 暂缓 / 先不 / 再说 / 还没定 / 看情况 / 待确认 / 不在本次范围
- **形态**：给了选项表却没给推荐；写了风险（⚠️）却没给结论；识别出可改进却没改；代码里冒出 `TODO`/`FIXME`；脚本里留了手动步骤
- **用户说**「这条先记着」

**不算未决**，别浪费文件：

- 已经拍板的 → 走 ADR；能从代码查到的事实 → 不写（`docs/` 下的单一信息源纪律）。
- **属于「用户手动操作域」的 → 不写、也别主动提**：这类事由用户亲手做，AI 不代办、不追问。**它是有意为之的取舍，不是遗漏**，落成 TODO 等于把已经关掉的问题重新打开。

## 落盘动作

1. **先读 `docs/todo/README.md` 索引表**。同主题已有文件就**追加到它的小节里**，不要新建。主题清单以那张索引表为准。
2. 确实要新建，才用 `docs/todo/YYYY-MM-DD-TODO-<主题>.md`。日期是**创建日期**，之后怎么改都不改名；主题写中文。
3. 文件头固定骨架（完整说明见 `docs/todo/README.md` 的「文件格式」节）：

   ```markdown
   # 待办：<主题>

   创建：YYYY-MM-DD · 状态：待办 · 优先级：高|中|低

   ## 背景
   为什么会有这条：现状 + 卡在哪

   ## 可选方案
   - **方案甲**：<做法> —— 代价：<…>
   - **方案乙**：<做法> —— 代价：<…>

   ➡️ 倾向：<哪个，为什么>（还没定就写清为什么定不下来，**别只列选项不给倾向**）

   ## 待确认
   <还缺什么 / 等谁拍板。没有写「无」。>

   ## 更新记录
   - YYYY-MM-DD：<改了什么>
   ```

   ⚠️ **头三行与「状态：待办」的写法不许动**——归档守卫脚本认它判结案。

4. **必须回 `docs/todo/README.md` 索引表补一行**：`| [文件名](./文件名) | 主题 | 待办 | 优先级 |`。状态变了也要回来改。
5. **反向处理一次**：本次真正拍板的结论 → 结论卡片进 `docs/adr/00NN-*.md`（编号递增，Status / Considered Options / Consequences，**只追加不改**；被否的选项写进 Considered Options），并在索引页的「已定，不用再想」表加一行，防止以后重新纠结。
6. **结案即归档**：一条待办的 `状态` 改成 `已解决` 后，`git mv` 进 `docs/todo/archive/`（**文件名不改**），把它从主索引表移到「已归档」区，并修文件内部 `../` 相对链接**退一级**。三步清单见 `docs/todo/archive/README.md`；CI 上有守卫脚本兜底。

## 每次回复结束前自检

- 我这次有没有「可以去改但没改」的东西？
- 有没有给用户留了选择却没说推荐哪个？
- 有没有把事推到以后——那是用户同意推迟的，还是我自己省事？
- 新落的文件进索引表了吗？
- 本次有没有把已结案的待办留在主表里（该归档没归档）？
- 我有没有在 README / CHANGELOG / ADR / 设计文档正文里开第二份待办清单？（**违规**，删掉并指回 `docs/todo/`）

完整收尾流程用 `/wrap-up`。
