# 收尾自检

按顺序做完 1–6，最后按第 7 节的模板回复。**任何一步发现东西都要真的落盘，不是只在回复里提一句。**

## 1. 把改动摆出来

```bash
git status --porcelain
```

这是本次「改了什么」的唯一真值，后面所有判断都基于它。

## 2. 捞出「提到过但没做的事」（最关键的一步）

扫描本次对话，逐条找下面三类，每条给出处置：

- **A 类 · 被推迟的决定**：出现「以后 / 回头 / 下次 / 暂缓 / 先不 / 还没定 / 看情况 / 再说 / 不在本次范围」
- **B 类 · 被识别但没修的问题**：写了风险却没结论、给了选项没给推荐、代码里新加了 `TODO`/`FIXME`、脚本里留了手动步骤
- **C 类 · 说过但没验证的假设**：「应该是这样」「大概率是」「估计是」这类没核实的话

| 情况 | 处置 |
|------|------|
| A/B 类，且现在确实定不了（缺信息、缺环境） | 写进 `docs/todo/`：同主题有文件就追加，没有就新建 `docs/todo/YYYY-MM-DD-TODO-<主题>.md`，并更新索引表 |
| A/B 类，但其实现在就能定 | **别拖延**：直接做掉或当场给推荐，然后写 ADR + 「已定，不用再想」表一行 |
| C 类 | 要么现在核实（跑命令/读代码，最多几分钟），要么写进 TODO 并标注「待验证」 |
| 纯噪音（无决策含义） | 丢弃——但要在报告里写明「XX 已判断为噪音，不落 TODO」 |

> 判据：三个月后自己读到这段对话会问「我当时到底决定了吗」——那就必须落 TODO。

## 3. 补文档与引用

对着第 1 步的文件清单，逐项走本项目「改代码 = 改文档」那条规则的「改动 → 该去哪儿改」表。特别检查：

- 有没有**移动/删除/重命名**过的文件 → `git grep -n '<旧名>'`，注释和脚本里的引用也要改
- 本次有没有把某条待办改成「已解决」→ 按未决事项那条规则归档进 `docs/todo/archive/`，并把它从 `docs/todo/README.md` 主表移到「已归档」区
- 有没有新加/改了 `scripts/*.sh`、`.github/workflows/*.yml`、环境变量 → `docs/operations/` 下要不要动
- 有没有新的结构性决策 → 需要补 ADR 吗

## 4. 跑守卫脚本

```bash
bash scripts/${LINK_CHECK_SCRIPT}
bash scripts/${TODO_ARCHIVE_SCRIPT}
bash scripts/${MODULE_TEST_SCRIPT}
```

红了就修到绿，**不要把红着的结果留在工作区**。

## 5. 更新会话工作台

本次动过文件的话，`docs/worklog/` 下应当有本次会话的工作台文档：

- 把「本轮状态」改成 `本轮完成`；若本次是在等用户回复，就写 `等你确认`
- 「现在在哪」「接下来要做什么」「卡住」三段按当前事实重写
- 流水账追加一行

⚠️ **别抄 git 状态**（哪些已提交、commit 哈希、推送范围）——那归 `git log`，抄进文档必然漂。
⚠️ **本步必须在第 6 步之前做完**；提交之后**不再回填**工作台，要补的内容等下一笔改动顺带带上。
⚠️ **不要写「已结束」**——AI 拿不到「会话结束」事件，那个状态永远不会被写入，等于一个死字段。
若整份文件没有任何实质记录，直接删掉，并在报告里说明删了。

## 6. 提议 commit

按 Conventional Commits 切分（`feat:` / `fix:` / `docs:` / `ci:` / `chore:` / `refactor:`），一次改动一个主题。
**不要替用户 commit**，只给出建议的 commit 列表。

## 7. 回复模板

```markdown
## 本次改了
- `<文件>`：<一句话>

## 未决事项
- 新增/更新 `docs/todo/YYYY-MM-DD-TODO-<主题>.md`：<一句话>
- （或：本次无未决事项）
- 判断为噪音、不落 TODO：<XX，因为……>

## 文档同步
- `<文档>`：<改了什么 / 为什么>
- 守卫脚本：全部通过

## 建议 commit
1. `<type>(<scope>): <标题>`
```
