# 配套 skill 的安装来源与维护

`fetch_skills.py` 只从官方仓库安装**已核验的固定提交**，不追上游默认分支的最新提交。
本文件说明它保证什么、不保证什么，以及以后怎么更新基线。

## 一、默认行为

```bash
# 离线预览：缺哪些、从哪拉、锁定到哪个提交、各自装到哪一步
python scripts/fetch_skills.py --dest ~/.claude/skills --check grill-with-docs design

# 经使用者确认后，按同一份锁定清单安装
python scripts/fetch_skills.py --dest ~/.claude/skills grill-with-docs design
```

- **只补缺项**：目标目录已有 `SKILL.md` 就跳过，绝不覆盖。
- **固定提交**：安装前从 `references/SKILL-SOURCES.json` 读取完整 SHA，只获取该提交。
- **严格目录**：固定提交下必须存在登记的上游目录；缺失即报错，不自动改用它处副本。
- **不执行内容**：只复制 skill 目录，不跑上游安装器、hooks、脚本或二进制。
- **不自动升级**：锁定清单变化不会改动本机已有 skill；上游变化也不会自动改锁定清单。

同一版脚手架、同一目标工具、同一组参数，默认得到同一批上游文件。

## 二、锁定清单

`references/SKILL-SOURCES.json` 按仓库登记：

| 字段 | 含义 |
|---|---|
| `commit` | 40 位完整提交号；安装与记录都用它 |
| `branch` | 只用于 `--outdated` 比较上游分支头，不决定安装版本 |
| `verified_at` | 最近一次核验日期 |
| `scope` | 核验覆盖的目录与分发口径 |

`fetch_skills.py` 里的 `SKILLS` / `DEPENDS` / `GROUPS` / `NOTES` 仍负责 skill 名称、上游目录、
依赖关系和安装范围说明，锁定清单不重复这些内容。

更新基线是人工流程：

1. 查看候选提交的差异；
2. 在隔离临时目录核验登记目录、依赖与复制边界（`impeccable` 的 `agent` / `claude` 两套都要看）；
3. 修改锁定清单；
4. 跑 `python -m unittest discover -s tests` 与 `python scripts/check_consistency.py`；
5. 审阅并单独提交。

不在本仓库的 CI 里定时访问上游，也不自动创建基线升级 PR。

## 三、`.fetched.json`

新安装的 skill 目录内会多一个 `.fetched.json`，记录：

- 来源仓库、完整提交、实际复制的上游目录；
- 目标工具分发类型（`agent` / `claude`）；
- 原始文件的相对路径与 SHA-256。

它用于回答「这个 skill 从哪来、原文件之后有没有被改过」。它不是：

- 上游签名或安全认证；
- 防篡改边界（本机文件包括这份记录本身都可被修改）；
- 对旧安装的追溯——此前安装、没有记录的一律显示「来源未知」，脚本不会猜测补写。

修改、删除已记录的原文件，或目录里多出未记录文件，`--outdated` 会分别报告。
额外文件不自动判为异常：缓存、运行时产物都可能出现。

## 四、`--check` 与 `--outdated`

`--check`：离线、不联网、不写盘；读取锁定清单与本机状态，用于安装前确认。

`--outdated`：联网、只读报告，不安装、不更新、不写元数据。

```bash
python scripts/fetch_skills.py --dest ~/.claude/skills --outdated grill-with-docs design
```

它分别显示：

- 本机是否安装、来源记录是否有效、原文件是否变化；
- 本机记录与当前锁定基线是否一致；
- 上游监测分支头与锁定基线是否一致。

**提交号不同不等于落后。** 第一版只查询分支引用，不判断祖先关系、提交数量或是否应升级；
输出使用「不同（尚未核验）」，不使用「落后」「建议立即升级」。

`--outdated` 的远程地址来自本仓库登记表，不读取 `.fetched.json` 里的地址去访问任意主机。

退出码：

| 码 | 含义 |
|---|---|
| 0 | 操作完成；报告里可以有版本差异、来源未知或本机修改 |
| 1 | 操作未完成：锁定清单损坏、网络查询失败、目标冲突或安装失败 |
| 2 | 命令行参数错误 |

上游有新提交本身不算失败，也不会自动升级。

## 五、失败与占用

- 目标位置是普通文件、符号链接，或目录存在但没有 `SKILL.md`：报告冲突，不覆盖、不清空。
- 一个仓库拉取失败：保留同批已完成的安装，继续处理其他仓库，最终退出码非零，并列出未完成项。
- 暂存目录每次唯一命名，只清理本次创建的内容；不接管其他进程留下的 `.partial`。
- 上游出现符号链接或特殊文件时拒绝安装并报告，不静默解引用。

## 六、明确不覆盖的部分

固定的是 **skill 源码安装基线**，不是运行时行为：

- `impeccable` 首次调用时会从 GitHub Releases 拉取并执行平台引擎；
- `web-design-guidelines` 每次使用还会联网拉最新规则；
- 上游 skill 自身未来新增的联网行为不在本脚本控制范围内。

因此，「固定提交」只证明这次装进来的源码来自哪里，不等于全部功能、安全性或运行时资源都已锁定。
