# 文档体系模板：搬了什么、改成什么样

源：一个跑了几个月的 Spring Boot + Vue 自用项目（下称「源项目」）。它的文档体系是**长出来的**，
不是设计的——每一条纪律背后都对应一次真实的翻车。本模板做的就是**把纪律搬过来、把自传剥掉**。

## 一、移植的三条红线

| 红线 | 为什么 |
|---|---|
| **剥硬引用** | ADR 编号、脚本名、专有路径、项目名——这些在新项目里要么不存在、要么编号不同，照搬会指到空处 |
| **剥自传式叙述** | 「某年某月我们踩过这个坑」是那个项目的历史。模板只留**判据 / 动作 / 命令**，不留编年史 |
| **保留纪律强度** | 规则的行数预算、`AGENTS.md` 只做路由、单一信息源、机械守卫——这些是体系能活下来的原因，不能为了「通用」而稀释 |

配套的两条机械检查（生成后跑）：模板里零命中 `ADR \d{4}` / 项目名 / 脚本名；零命中 `20xx-xx-xx`。

## 二、逐项处理

| 部件 | 处理 | 说明 |
|---|---|---|
| 常驻规则 4 条 | **移植重写 + 改名** | 规则文件改名成中性英文名（`unresolved-items` / `docs-with-code` / `session-log` / `design-tools`），这样文档正文里指到它们时不会出现「源项目专属的规则名」。每条 ≤100 行的预算保留 |
| `/wrap-up` 收尾命令 | **移植重写** | 三件套的第三件（规则让 AI 知道 / 命令让 AI 记得做 / 脚本+CI 让 AI 不做就过不去）。脚本名用 `${LINK_CHECK_SCRIPT}` 之类的占位符，生成时才变成真名 |
| `AGENTS.md` | **参数化** | 只做路由 + 收尾清单，不复述规则内容（它每次会话也会加载，复述＝重复的上下文税） |
| 文档地图 + 目录树 | **骨架化，成对处理** | 见下节 |
| ADR 说明 | **移植重写** | 收录标准三条（难反转 / 不看上下文会意外 / 有真实取舍）是通用的；源里「格式照 0006 抄」改成**内联一份格式模板** |
| TODO 说明 | **移植重写** | 带上 v2 四段格式（`背景` / `可选方案`+`➡️ 倾向` / `待确认` / `更新记录`）。这条格式是被真用过的，不是新设计的 |
| worklog 说明 | **原样复制** | 纯格式文件，无项目专属引用 |
| 开发协作 | **骨架化** | 分支/提交/PR 的结构保留，内容换占位——协作现实每家不同 |
| `.gitattributes` / `.gitignore` | **移植 / 补写** | `.sh` 必须 LF 是通用约束；`.gitignore` 是**源计划漏了后来补的**（不补的话「先装依赖、后 git add」会把 `node_modules` 带进库） |
| 根三件套 | **骨架化** | README / CONTEXT / CHANGELOG（Keep a Changelog 结构保留） |
| `PRODUCT.md` / `DESIGN.md` | **只建空文件** | 它们是 **impeccable** 的产物：`PRODUCT.md` 由 `impeccable init` 写实，`DESIGN.md` 由 `impeccable document` 从 `tokens.css` 派生。**模板不填内容、不留骨架** |
| 守卫脚本 4 条 | **参数化** | 逻辑通用，改掉硬编码路径与模块名 |

**源项目里刻意不搬的**：业务味的 Java 类、e2e 跑法、AI 探索测试任务书、具体色值与实测数值。理由分别见
`TECH-STACK.md` 与 `TESTING-SYSTEM.md`。

## 三、地图与树为什么必须成对

`docs/README.md`（四列文档地图）与 `docs/目录结构.md`（两棵带注释目录树）是**同一批文件的两个视角**：
- **树看形状**（谁在谁下面）；
- **表看用途与真相源**（这是干嘛的、以谁为准）。

两者互相指向，且「改一处要同步另一处」这条写在树的维护节里。**拆散搬会导致新项目一生成两份文档就天生对不上**——
那正是源项目里「文档漂移」的成因之一。

树的组织方式（**两棵树**）也是要沉淀的：
1. **仓库根视图**：画「文档散在哪」（根文件 + `.codebuddy/` + `scripts/` + `deploy/` + 各子工程；代码目录只标位置）；
2. **`docs/` 视图**：画体系内部。

树内路径一律用**行内代码**（不少是示意路径如 `NNNN-*.md`，写成链接会被链接守卫误报断链）。

## 四、模板里「空目录 + .gitkeep」的用意

`docs/adr`、`docs/operations`、`docs/testing` 等在骨架阶段是空的，但仍要建目录并放 `.gitkeep`：
① git 不跟踪空目录，不补占位下次生成结构就缺一块；② 文档地图里指过去不会断链。
带 `--with-testing` / `--with-ops` 时，内容文档会落进这些目录，`.gitkeep` 就不会再生成。
